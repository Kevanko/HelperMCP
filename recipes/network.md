# Диагностика интернета и VPN на Windows 10/11

Начни с `system {sections:["network","reach","perf"]}` и `net_check {mode:"quick"}`.
Это инвентаризация и сравнение путей, а не разрешение менять настройки компьютера.
Сохрани код сеанса и текущий рабочий путь Helper. Не переключай VPN/TUN или zapret
ради проверки через Ethernet: выбирай `interface_index` из отчёта network.

## Быстрые вызовы

Аргумент `session` добавляется ко всем вызовам на общем MCP endpoint.

| Задача | Вызов |
|---|---|
| Сравнить текущий TUN и доступные адаптеры | `net_check {mode:"quick"}` |
| Проверить конкретный Ethernet | `net_check {mode:"sites",interface_index:14,urls:["https://www.youtube.com/","https://discord.com/"]}` |
| Проверить выбранный TUN | Тот же вызов с индексом TUN; не включать другой профиль |
| Сравнить DNS | `net_check {mode:"dns",interface_index:14,urls:["https://discord.com/"],resolver:"8.8.8.8"}` |
| Повторить задержки | `net_check {mode:"sites",interface_index:14,urls:["https://www.microsoft.com/"],samples:5,timeout_ms:3000}` |
| Ограниченная загрузка | `net_check {mode:"speed",interface_index:14,urls:["https://speed.cloudflare.com/__down"],samples:1}` |
| Доступность адреса VPN | `net_check {mode:"vpn",interface_index:14,endpoints:[{host:"vpn.example.com",port:443,tls:true}]}` |
| Адреса из локального экспорта подписки | `net_check {mode:"inventory",config_path:"C:\\Users\\Friend\\Downloads\\subscription.txt"}` |
| Задержки до и во время небольшой загрузки | `net_check {mode:"load",interface_index:14,urls:["https://www.microsoft.com/"],load_url:"https://speed.cloudflare.com/__down"}` |
| RKN Checker на конкретном адаптере | `net_check {mode:"rkn",interface_index:14}` |
| RKN Checker только нужных сайтов | `net_check {mode:"rkn",interface_index:14,urls:["https://discord.com/","https://www.youtube.com/"]}` |

Индекс 14 приведён для примера: обязательно подставляй индекс проверяемого ПК.
Неверный или выключенный адаптер даёт ошибку, без скрытого перехода на default.
В RKN режиме индекс 0 означает только текущий маршрут. Нужен установленный `uv`;
он запускает отдельный Python с закреплённым `rkn-block-checker==0.6.0`.
Если uv отсутствует, Helper пытается подготовить его portable-копию.
Первая загрузка пакета/интерпретатора может не пройти через повреждённый интернет:
это ошибка подготовки проверки, а не результат проверки сайтов. Не устанавливай
пакеты в окружение чужих приложений. Нативным режимам Python не нужен.

## Как читать результат

- Ethernet binding означает выбранный интерфейс для собственных IPv4-сокетов.
  WinDivert/WFP/zapret всё ещё могут их перехватывать. Если они активны, называй
  результат «Ethernet при работающем фильтре», а не «чистый интернет без zapret».
  Перечень служб показывает состояние службы, но не доказывает отсутствие всех
  драйверов и правил перехвата. Не останавливай фильтр, удерживающий удалённую связь.
- Каждый путь содержит DNS-ответы, фактический IP назначения и локальный адрес
  сокета, TCP connect, TLS handshake, первый байт, HTTP status и прочитанные байты.
  Системный DNS общий; в нативных проверках DNS адаптера и альтернативный UDP DNS
  запрашиваются отдельно через этот адаптер. В RKN при выбранном адаптере
  дочерний процесс заменяет разрешение имён запросами
  UDP DNS через этот же адаптер. В `dns_observations` указаны фактические резолверы
  и ответы, включая переход к публичным DNS. Без индекса RKN использует системный DNS.
- `198.18.0.0/15` — fake-IP. Не отправляй такой адрес через физический адаптер
  и не объявляй отказ доказательством блокировки настоящего сервера. Сравни ответы
  альтернативных DNS. Различие адресов само по себе нормально для CDN и не доказывает
  подмену. Не записывай новый DNS в Windows ради диагностики.
- TCP успешен, TLS падает: проверь ошибку сертификата, время ПК, антивирусный HTTPS
  фильтр, SNI и сервер. Один timeout/reset не доказывает блокировку SNI или IP.
  TLS-проверка сертификата включена. Не отключай её ради зелёного результата.
- HTTP 401/403/429/451 — содержательный отказ; 200 с HTML не доказывает видео,
  авторизацию, голос Discord или игровой UDP. Redirect не проходится автоматически.
  Короткая страница и link speed не измеряют пропускную способность линии.
- `samples` — повторы соединений, доля ошибок не равна потере ICMP-пакетов.
  ICMP не требуется для доступа HTTP. Сравни разброс TCP/TLS/TTFB и ошибки под
  обычной нагрузкой пользователя. Не запускай насыщение канала без необходимости.
- CPU/RAM и адаптерные счётчики показывают нагрузку в момент измерения. Для
  отделения перегрузки ПК от bufferbloat нужны сопоставимые замеры простоя/нагрузки;
  одного CPU среза недостаточно. Не обвиняй ядро/драйвер по имени процесса.
- В режиме `load` скачивается максимум 3 МиБ, и измеряются задержки контрольного
  адреса до и во время этой попытки. Проверяй `overlapping_samples`: короткая
  страница может загрузиться раньше измерения и не создать заметной нагрузки.
  Это не доказательство насыщения канала или bufferbloat.
- По умолчанию отчёт содержит min/median/max, статусы и ошибки. `detail:true`
  добавляет отдельные измерения. В журнале действий сохраняются режим, индекс и
  количество целей, без сетевых URL и содержимого экспорта.

## Подписки Happ, Incy, Koala и другие клиенты

Сначала прочитай текущий профиль и журналы через файлы/интерфейс клиента, не меняя
его состояния. Из подписки/конфига извлекай только host, port и транспорт, без
UUID, пароля, полного subscription URL и private key. Проверяй до восьми endpoints
за вызов. Режим `inventory` читает локальные JSON/YAML/URI/base64 URI экспорты,
возвращает адреса и транспорт, без авторизационных данных. Для больших экспортов
по умолчанию возвращаются 64 уникальных сервера: `count` — общее число,
`returned_count` — размер страницы, `next_offset` — начало следующей. Передай его
в `inventory_offset`; `inventory_limit` задаёт размер страницы от 1 до 128.
YAML поддерживает вложенные и inline-списки, anchors/aliases и merge keys.
Повторяющиеся или сложные ключи, чрезмерная вложенность и разрастание ссылок
отклоняются. Ссылки на удалённых провайдеров не загружаются. Библиотека YamlDotNet
18.1.0 загружается с relay при первом YAML-разборе и проверяется по SHA256;
последующие сеансы используют проверенный локальный кэш. Файл экспорта остаётся
на ПК. Непрозрачные базы клиентов и SSR требуют другого формата экспорта.
Режим `inventory` не применяет подписку и не запускает её профили.
VLESS/REALITY/VMess/Trojan требуют настоящего протокольного подключения; стандартный
TLS к REALITY может намеренно отказывать. Hysteria2/TUIC/QUIC работают через UDP:
TCP на том же порту ничего не доказывает. Для полной проверки нужен изолированный
экземпляр совместимого ядра с отдельным loopback proxy и привязанным outbound,
без TUN/служб/системного proxy; используй его только при наличии подходящего ядра
и проверенной конфигурации. Не называй TCP-пробу проверкой всех серверов подписки.

Режим `profile` выполняет HTTP-проверку через уже установленный Mihomo:
передай абсолютный `core_path`, локальный YAML/JSON с `proxies`, исходный индекс
`profile_index` (с нуля, до удаления дублей в inventory) и один-два URL без секретов.
URI/Xray/sing-box экспорты для этого режима нужно сначала экспортировать в формат
Mihomo. Цепочки `dialer-proxy` и отключённая проверка сертификата отклоняются.
Это отдельная проверка выбранного узла, а не воспроизведение всех правил клиента.

```json
{"mode":"profile","config_path":"C:\\Repair\\export.yaml","core_path":"C:\\Apps\\mihomo.exe","profile_index":0,"interface_index":14,"urls":["https://www.microsoft.com/"],"samples":1}
```

Helper создаёт приватную временную конфигурацию с одним профилем и loopback proxy
со случайным паролем, отключает TUN/DNS и привязывает outbound к указанному адаптеру.
Без индекса используется текущий маршрут, включая действующий TUN. Исходный клиент,
экспорт и системные настройки не меняются. Job Object ограничивает жизнь своего
ядра и завершает его при закрытии Helper. После проверки процесс и конфигурация
удаляются; проверь `cleanup_complete`. Журналы ядра и credentials не возвращаются.
В режиме подтверждений запуск требует согласия на выполнение команды.

`profile_http_verified` означает успешный HTTP через выбранный профиль; неверные
credentials, HTTP 403 и недоверенный сертификат не дают этот статус. Одна ошибка
не различает отказ авторизации, маршрутизации и цели. Голос/игровой UDP, видео,
авторизация приложения и остальные профили остаются отдельными проверками.
Лимиты: `samples` 1–2, `profile_timeout_s` 3–15, тело ответа до 64 КиБ.

## Исправления и заключение

Сначала укажи наблюдаемые факты, затем гипотезы и что осталось непроверенным.
Не обещай конкретную причину, если измерения её не различают. Исправляй только
подтверждённую настройку: перед изменением сохрани точное старое значение вне
репозитория, подготовь узкий откат и независимый доступ. Не выполняй сетевые
reset, смену DNS, удаление маршрутов, перезапуск адаптера, VPN/TUN/zapret через
единственный удерживающий связь канал обычной командой без защиты. Для порученных
сетевых изменений используй [сценарии с независимым откатом](network-recovery.md)
через `net_recover`: задание восстановления должно пройти preflight до первого
изменения. После правки повтори те же проверки и
проверь нужное приложение. Если Helper offline, не утверждай исправление.
